# 显影｜交付里程碑与验收

> **计划 ≠ 已完成。** 本页以 LocalPixt/显影原项目已有的 README、文档和 W3 验收日志为依据制定。具体技术工作优先使用原项目内部任务和报告；本页仅提供个人学习与毕业设计之间的协调视图。

## 验收现状：只勾选有记录的事项

- [x] 桌面检索 / 端侧推理的技术可行性已有验证报告。
- [x] W1 原生 Android 应用骨架与模型管理已有完成记录。
- [x] W2 受控图片索引、查询与恢复测试有通过记录。
- [x] W3 用户授权下的真实相册索引 / 查询有 PASS 记录（2026-10-18）。
- [x] W3 查询结果与详情 UI 流程有 PASS 记录（2026-10-19）。
- [ ] 完整系统功能清单与毕业设计题目逐项对齐、全部验收。
- [ ] 权限拒绝 / 部分授权 / 大图库增量维护等边界测试全面收口。
- [ ] 正式量化实验 E1–E5（哪些必做、哪些裁剪先与导师确认）。
- [ ] 论文图表与复现实验对应、毕业设计报告成稿。
- [ ] 可展示 APK、使用说明、演示与最终技术冻结。
- [ ] 学校正式开题、中检、评阅、答辩流程全部完成（不得提前勾选）。

## 阶段 1：2026 年 10—11 月｜核心 Android 产品稳定化

- [ ] 重新对照**目前最新**的真机测试结果与项目 Issue/任务文档，确认主流程缺口。
- [ ] 完整核对真实相册的权限授权/拒绝路径，保证照片不出设备。
- [ ] 核心能力优先：模型加载、相册扫描、索引、中文检索、结果详情、异常恢复。
- [ ] 对关键行为增加可复现的回归证据与可靠错误处理。
- [ ] 将已测结果映射到论文章节；不无休止追求模型调参收益。

**验收门**：有稳定的端侧主流程、明确的未实现清单和复现证据；不是以“Agent 说完成”为准。

## 阶段 2：2026 年 11—12 月上旬｜四级前受控推进

- [ ] 每周只选 1 个 MVP 缺口修复或论文证据整理任务。
- [ ] 非必须的 2B 对话 Agent、YOLO 打标、额外模型方案等停止主动扩展。
- [ ] 若真机离线/有资源冲突，改做文档、单元测试分析和下一轮验收计划。
- [ ] 确保 **12 月 12 日四级** 的英语复习与数学基础任务先被安排。

**验收门**：项目状态透明、阶段性成果有记录；不需要四级前做完全部产品。

## 阶段 3：2026 年 12 月中旬—2027 年 1 月｜正式实验与交付包

- [ ] 按核心价值优先选择必要评测：检索质量、速度、索引维护与过滤策略等。
- [ ] E1—E5 中哪些纳入正式论文，以导师/学院要求为准；未运行的实验不能写成已完成。
- [ ] 准备可复现的实验表格、图表、失败案例和安全脱敏的演示资源。
- [ ] 让 APK / 主要功能 / 说明文档 / 论文素材能对齐互相支持。

**验收门**：至少有一个可展示的完整 MVP 与可核实的实验包，附不通过项清单。

## 阶段 4：2027 年 2 月｜提前技术冻结

- [ ] 形成候选稳定版 APK 和可重复演示的主流程。
- [ ] 对照学校论文/开题/中检模板完成初稿或结构化素材包。
- [ ] 将功能边界、性能限制、未来改进写清；不为追求“完美”推迟冻结。
- [ ] 形成**官方毕业流程待办**，以后只按学校时间点补交材料或接受意见。

**验收门**：提前技术交付尽量结束，为 2027 年数学强化、408、找实习/工作让出长期时间。

## 与考研协调的时间盒

| 时段 | 毕设建议投入 | 前提 |
| --- | --- | --- |
| 2026.10—2026.12.12 | **3–5h/周（上限型建议）** | 数学 12–14h/周、四级英语 7–9h/周优先；不启动别的可选项目 |
| 2026.12.13—2027.02 | **5–7h/周（视课业灵活调整）** | 数学基础继续推进、考研英语与 408 不长期停顿 |
| 2027.03 起 | **常态按需维护** | 只处理学校要求或真实缺陷，不重开功能大扩张 |

这里的小时数不是硬性的额外工作指标；若课表已经满负荷，要先裁剪扩展功能与 OS/竞赛，而不是挪用睡眠。

## 不可以混淆的状态

- **实验 PASS**：某一次设备、用例和判据通过。
- **MVP 完成**：主链路功能在定义范围内达到可交付标准。
- **技术提前冻结**：毕业设计内容准备充分，可以等待学校的正式程序。
- **正式毕业设计完成**：学校的相关审核、文书与答辩程序全部通过。

原项目里仍需保留完整、可复现的私人测试证据；本公开 Vault 只存项目方向、状态摘要和计划。
